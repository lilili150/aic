## 判断

1. exp002 在相同划分与评价口径下 mIoU 提升 0.01320，8 个有效类别全部提升，是可靠正向结果，保留为当前最佳配置。
2. Barren（最低）、Vehicle、Background 三类仍是短板；Building/Road/Water 从 512→768 获益最大，Barren 增益最小（+0.00783），说明分辨率不是其主导杠杆。
3. exp002 最佳轮次=训练末轮 30，未见平台期；当前最可能未被用尽的变量是学习率曲线与训练轮数（二者必须分开单独实验）。
4. 官方硬约束：不允许多模型集成，最终提交只含一个模型；提交需与测试图同名、1024×1024、单通道、非 Palette、像素值∈0~8，格式或尺寸不符记 0 分；预训练仅限学术公开权重，不得使用额外数据；类别 ID↔名称以数据包 Label.txt/样例 mask 复核为准（勿按官网列表文字顺序推断 ID）。
5. 训练链路健康（CE ignore=0、同步翻转、AMP、修复后评价）；主要风险集中在工程闭环与缺失观测，不阻塞继续调模型，但影响成果复用与上线。

## 问题定位

### P0（优先处理）

- 无真正断点续训：一次约 100 分钟，中断即丢失本轮回滚；应补定期 `last` checkpoint + `--resume`。
- 无推理/提交链路：缺对官方测试集的 `predict.py` 与"尺寸/通道/ID/同名"提交自检器，exp002 最佳模型目前无法产生正式成绩。

### P1（改进空间）

- 无学习率调度与 warmup（对应 exp003 单变量实验）。
- 增强极弱（仅同步水平翻转 + ImageNet 归一化），无颜色/尺度变化。
- 类别不平衡无任何处理，Barren/Background/Vehicle 三类显著低于其余类别。
- 评价分辨率（512/768）与官方提交分辨率（1024）不一致；最终选型前应做一次 1024 口径验证集重评。
- best 模型只按单次验证 mIoU 挑选，验证集仅 1399 张，存在小样本噪声。
- 训练记录缺 `predicted_ignore_ratio` 观测（exp001=0.00000，exp002 无记录）。勘误：预测为 0 的像素等价于该真值类的一个 FN，不会系统性高估 mIoU，但 0 通道是"更温和的错误出口"，应作为质量门禁统计。

### P2（低风险 / 工程整洁）

- 三份并行 mIoU 实现易再次漂移（含一份死代码）；`smoke_test.py` loss 口径与训练不一致；`make_split.py` CSV 含过期绝对路径列；`docs/suggestions/` 存在同名重复副本且建议编号跳号；`run_config.json` 缺 python/torch/CUDA 版本元信息。各自作为独立小步处理。

## 结论与下一步

1. 立即（代码可靠性，非模型变量）：补断点续训、训练内记录 Ignore 预测比例、收敛评价实现并加单测。
2. 上线前：新增 `predict.py` + 提交自检器；用 exp002 best_model 打通初赛测试集（500 张）推理提交（复赛前窗口），并准备 docker 复现材料。
3. exp003（单变量）：以 exp002 为基准，只加学习率调度（warmup + cosine/poly），观察第 30 轮后是否继续提升；不得同时延长轮次。
4. 后续候选（每个独立成实验）：轻度颜色增强 → CE + Dice → 温和类别加权 → 8 通道标签重映射（0→255）→ SegFormer B1/B2。

所有实验沿用同一 `train/val` 划分与同一评价代码，以总 mIoU + 每类 IoU 共同决策，不做任何集成式手段。
