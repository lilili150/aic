# exp002 输入尺寸 768 实验分析

## 实验目的

在 exp001 正式基线基础上，只将输入尺寸从 `512 x 512` 改为 `768 x 768`，验证更高输入分辨率是否能改善语义分割结果。数据划分、模型、batch size、学习率、Loss 和增强保持不变。

## 配置与结果

| 项目 | exp001 正式基线 | exp002 |
|---|---:|---:|
| 模型 | SegFormer MIT-B0 | SegFormer MIT-B0 |
| 输入尺寸 | 512 x 512 | 768 x 768 |
| Batch Size | 2 | 2 |
| 学习率 | 6e-5 | 6e-5 |
| Epoch | 30 | 30 |
| 验证样本数 | 1399 | 1399 |
| 最佳 epoch | 25 | 30 |
| 验证集 mIoU | 0.74939 | 0.76258 |
| 相对 exp001 | - | +0.01320 |

exp002 结果文件：`outputs/results/exp002_size768/`。训练耗时约 `101.1` 分钟。

## 判断

1. exp002 在相同验证划分和评价代码下 mIoU 提升 `0.01320`，这是目前可靠的正向结果。
2. 8 个有效类别全部提升，没有出现以总体分数换取单个类别提升的情况。
3. Building、Road 和 Water 增益最大，说明更高输入分辨率确实保留了更多空间细节；Vehicle 提升约 `0.01016`，但仍是较低类别之一。
4. 第 30 轮仍是最佳轮次，没有证据表明 30 轮已经达到平台期。后续若继续研究 768，应优先考虑学习率调度或延长训练，但那将是新的变量。

## 结论

保留 `exp002_size768` 作为当前最佳实验。后续推理优先使用 epoch 30 的 `best_model`。下一轮不应同时加入增强、Dice 或类别权重；建议先做一个独立的学习率调度实验，或在资源允许时单独比较 768 输入下更长训练，但两者不要合并。
