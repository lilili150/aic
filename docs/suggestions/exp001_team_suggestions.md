## 三、AI 技术审查

### P0：先修复 Ignore 像素的评价逻辑

当前 `compute_miou()` 和 `evaluate()` 虽然不计算类别 0 的 IoU，但没有把真实标签为 0 的像素从其他类别的并集中排除。如果模型在 GT Ignore 区域预测为 1～8，当前代码会错误地把它计入对应类别的 FP。

正确做法是在评价时先建立有效像素掩码：

```python
valid = targets != IGNORE_INDEX

for class_id in range(1, NUM_CLASSES):
    predicted = (predictions == class_id) & valid
    actual = (targets == class_id) & valid
    union = (predicted | actual).sum().item()
    intersection = (predicted & actual).sum().item()
```

`evaluate()` 中同样处理：

```python
valid = masks != IGNORE_INDEX

for class_id in range(1, NUM_CLASSES):
    predicted = (predictions == class_id) & valid
    actual = (masks == class_id) & valid
    total_intersection[class_id] += int((predicted & actual).sum())
    total_union[class_id] += int((predicted | actual).sum())
```

这一步不需要重新训练。加载 Epoch 25 的 `best_model`，重新跑完整验证集即可。修复后应记录：

1. 新的总 mIoU；
2. 8 个有效类别的新 IoU；
3. 预测为类别 0 的像素数量及比例；
4. 修复前后差值。

### P0：修正术语和数据边界

- 5597 张用于训练，1399 张用于本地验证；这 20% 应称为验证集，不是测试集。
- 官方 `test_1` 才是初赛测试集，不得用于训练、选择模型或调参。

### P1：检查随机划分是否造成近重复泄露

当前 `make_split.py` 使用固定随机种子进行普通随机划分，能够复现，但没有执行来源分组、相邻 Patch 检查或近重复检查。官方数据由大图切成 Patch 后重新排序，因此需要至少补充：

1. 训练集与验证集的精确重复检查；
2. 感知哈希或图像特征相似度检查；
3. 各类别像素占比与图片出现率对比；
4. 对高相似跨集合样本进行人工复核。

在确认泄露风险前，`0.74514` 只能视为当前随机划分下的内部成绩。

### P1：补齐可视化与提交验证

正式优化前应增加：

- 原图、GT、预测 Mask 三联图；
- 每类预测像素分布；
- 混淆矩阵；
- 高 Loss / 低 IoU 样本列表；
- `test_1` 推理脚本；
- PNG 单通道、非 Palette、1024 × 1024、文件名和像素 ID 自动检查器。

### P1：9 通道输出可以保留，但需监控类别 0

当前模型输出 9 通道并用 `ignore_index=0` 忽略目标类别 0，这种实现可以继续作为当前基线，不应与其他改动同时修改。但必须统计模型在有效 GT 像素上预测为 0 的比例。

后续可以单独比较 8 通道方案：将原始 0 映射为 255，原始 1～8 映射为训练标签 0～7，推理后再加 1 恢复官方 ID。该方案必须作为独立实验，不能与新 Loss 或新模型同时加入。
